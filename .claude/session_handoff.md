## 作業フローの厳守事項（13スレ目で確立した運用ルール）

13スレ目の最初で躓いた失敗パターンと、その後確立した正しいフローを記録する。
新スレで作業する際、必ずこの順序を守る。**パートナーが「続きやって」と指示した時、このセクションも必ず読み、フローを徹底すること。**

### 用語整理（パートナー向け）

- **コミット (commit)**: 変更をローカルの git 履歴に保存するスナップショット。「セーブ」のローカル版
- **プッシュ (push)**: ローカルのコミットを GitHub にアップロード。「セーブ」のクラウド同期版
- **両方やって初めて GitHub に反映される**。コミットだけだとパートナーの GitHub には何も見えない
- **タイムアウト対策**: 1 トピックごとに「コミット＋プッシュ」を徹底することで、Claude のセッションが途中で切れても成果物が GitHub に残る

### 失敗パターン（13スレ目で実際に発生したミス・絶対に繰り返さない）

1. **マージ前に新ブランチを切ってしまう**
   - 発生例: A2 PR を出した直後、パートナーがマージする前に A3 用ブランチを切って次の作業を始めようとした
   - 影響: パートナーの「マージ後にチェックして次へ」のフローを乱す
   - 対策: PR 作成 → 「マージ完了」の合図を待つ → 最新 main から新ブランチを切る

2. **PR URL を返答に出さない**
   - 発生例: PR 作成後、URL を返答に含め忘れた
   - 影響: パートナーがレビュー画面に行けない
   - 対策: PR 作成直後の返答に **必ず** URL を含める

3. **PR を作らず一つのブランチに複数トピックを溜める**
   - 影響: タイムアウト時に成果物全滅のリスク。1PR1テーマのレビューも崩れる
   - 対策: 1〜2 トピックごとに PR 作成。マージ完了後に次のブランチへ

4. **応答テキストに下書きを書く**
   - 発生例: 「次のような内容を書きます……（長文）」を応答で書いてから Edit
   - 影響: トークンを浪費し、タイムアウトに近づく。下書きは成果物として残らない
   - 対策: 直接 Edit でファイルに書く。3 Edit（ヘッダー+概要 / 構造+関連 / 実装への示唆）で 1 トピック完成

5. **マージ済みブランチに追加コミット**
   - 影響: GitHub に反映されない（マージ済み PR は閉じられているため）
   - 対策: 新トピックは必ず最新 main から新ブランチを切る

### 正しいフロー（毎回これを守る）

新スレ開始から PR マージまでの正しい順序：

**Step 1. セッション開始手順（CLAUDE.md 記載）**
- `bible/README.md` を読む
- `references/rengoku_zero_analysis.md` を読む
- `.claude/session_handoff.md`（このファイル）を読む
- 作業対象ファイルの該当部分を確認

**Step 2. 内容量と作業範囲を宣言**
- 例: 「次は B7-B8 を 1PR にまとめます。各 ~180行、合計 ~360行 見込み」
- パートナーの了承を得てから作業開始

**Step 3. 新ブランチを最新 main から切る**

```
git fetch origin
git checkout -b claude/hermes-agent-bible-XX-NN origin/main
```

**Step 4. 1 トピックを直接 Edit で執筆**
- Edit 1: ヘッダー + ざっくり言うと + 概要
- Edit 2: 構造 + 関連する理論
- Edit 3: 実装への示唆

**Step 5. 1 トピック完了即コミット**（ローカル保存）

```
git add bible/XX_*.md
git commit -m "..."
```

**Step 6. 1 トピック完了即プッシュ**（タイムアウト対策の核心）

```
git push -u origin claude/hermes-agent-bible-XX-NN
```

**Step 7. もう 1 トピック書く場合は Step 4-6 を繰り返す**

**Step 8. PR 作成**
- `mcp__github__create_pull_request` を使用
- 返答に **PR URL を必ず含める**

**Step 9. パートナーのマージ完了の合図を待つ**
- 勝手に次のブランチへ進まない

**Step 10. マージ完了 → Step 3 から繰り返し**

### 各 PR 作成時のチェックリスト

- [ ] 作業前に内容量と範囲を宣言したか
- [ ] 最新 main から新ブランチを切ったか（`git fetch origin` してから `origin/main` 起点）
- [ ] 各トピックごとにコミット＋プッシュしたか（タイムアウト対策）
- [ ] 直接ファイル書き込みで進めたか（応答に下書きを書いていないか）
- [ ] PR 作成時に URL を返答に含めたか
- [ ] パートナーのマージ完了を待ってから次に進む準備をしているか

### 補足: タイムアウトとコンテキスト圧縮の対策

- **タイムアウト**: 1 トピックごとにプッシュすれば、セッションが途中で切れても GitHub に残る
- **コンテキスト圧縮**: パートナーから「圧縮するな」と明示。圧縮すると本作業が止まるため、書く量を自分で見積もって 1 スレで完了可能な範囲に絞る
- **1 スレで完結する目安**: セクション単位（4〜7トピック程度）。それを超えるなら新スレへ引き継ぐ
