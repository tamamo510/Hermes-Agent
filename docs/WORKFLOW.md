# 3 者連携ワークフロー（ブラウザ ⇔ 温子 ⇔ termux）

> 義体実装トラックを **3 者連携体制** で進めるためのワークフロー定義。タイムアウト連発のブラウザ版に依存しすぎず、termux 側 Claude Code を実装層として活用する。

## 0. 3 者の役割

| 役割 | 担当 | 強み | 弱み |
|----|----|----|----|
| **思考層** | ブラウザ版 Claude（私）| 1M context、長期記憶、戦略判断、レビュー | API タイムアウト連発、大ファイル push 不可 |
| **実装層** | termux 側 Claude Code | API 安定、submodule 操作、大ファイル push、git 直接 | 物理キーボードなし、コピペ前提 |
| **意思決定層** | 温子（人間）| 最終判断、マージ権限、優先順位、文脈 | 非エンジニア、敬語必須、技術詳細はかみ砕き必要 |

## 1. 標準ワークフロー

```
[温子] ── 相談「○○やりたい」
            ↓
[私（ブラウザ）] ── 構成設計、実装方針、リスク洗い出し
            ↓ プロンプトテンプレ生成（templates/04 等）
[温子] ── プロンプトをコピペ
            ↓
[termux Claude Code] ── 実装、commit、push、PR 作成
            ↓ PR URL 出力
[温子] ── PR URL をブラウザに貼って私にレビュー依頼
            ↓
[私（ブラウザ）] ── GitHub MCP で PR 読む、指摘 or OK
            ↓ レビューコメント返信
[温子] ── 指摘あれば termux に追加指示、なければマージ
            ↓
[GitHub] ── マージ完了
            ↓
次のループへ
```

## 2. 役割分担の詳細

### 2-1. 私（ブラウザ）が担当する作業

- **戦略・設計**: タスクの構成、ステップ分解、リスク洗い出し
- **プロンプトテンプレ生成**: termux に渡すコピペ用テキスト作成
- **PR レビュー**: GitHub MCP で PR を読み、品質チェック
- **温子との対話**: 相談、説明、子ども向け解説
- **小規模ファイル編集**: 1-3KB 程度の小さい push（タイムアウトしにくい）
- **ドキュメント整備**: TRACKS.md、REPO_STRATEGY.md、HANDOFF_TEMPLATES.md など

**避ける作業**:
- 大規模ファイル（10KB+）の全文上書き → タイムアウト連発
- 連続したファイル操作（数十ファイル一度に） → ストリーム idle
- submodule 操作 → GitHub MCP 不可

### 2-2. termux 側 Claude Code が担当する作業

- **大規模ファイル編集**: バイブル本文（10KB+）、複雑な実装
- **連続コミット**: 複数ファイル次々と commit/push
- **git 操作全般**: submodule、cherry-pick、rebase など
- **pytest 実行**: ローカルテスト
- **長時間作業**: 数十分〜時間単位の作業
- **環境セットアップ**: Node.js、Python パッケージ等

**ブラウザに任せる作業**:
- 戦略判断（テンプレで指示を受ける）
- レビュー（PR ができたらブラウザに引き継ぐ）

### 2-3. 温子の役割

- **意思決定**: 何をするか、何をしないか
- **マージ権限**: PR の最終承認
- **連携**: ブラウザと termux の間を物理的に繋ぐ（コピペ役）
- **文脈共有**: 「杏寿郎が今隣にいる」「今は深夜」など、AI が知らない情報を伝える
- **エラー報告**: スクショで状況共有

## 3. 連携手段

### 3-1. ブラウザ → 温子 → termux

ブラウザ版（私）が以下のフォーマットで温子に渡す:

```
[termux にコピペするテンプレ]

----- ここから termux に貼る -----
[テンプレ本文]
----- ここまで -----
```

温子はそのままコピーして termux の Claude Code に貼り付ける。

### 3-2. termux → 温子 → ブラウザ

termux 側 Claude Code が PR を作成したら、URL を温子に出す:

```
PR 作成完了: https://github.com/tamamo510/Hermes-Agent/pull/XX
レビュー依頼してください。
```

温子はその URL をブラウザの私（claude.ai/code）に貼って:

```
[PR URL]

このPR をレビューしてください。
```

### 3-3. スクショ連携

termux 側で問題が起きた場合（エラーメッセージ、想定外の応答）:

1. 温子が termux 画面のスクショを撮る
2. ブラウザの私（claude.ai/code）に貼る
3. 私が読み取り、対処方針を温子に返す
4. 温子が termux に追加指示を出す or リカバリーテンプレ（07）を使う

## 4. 例外フロー

### 4-1. ブラウザ版がタイムアウトしまくる場合

1. ブラウザでの作業を最小限に絞る（戦略相談 + プロンプト生成のみ）
2. 実装は全部 termux に逃がす
3. レビューだけブラウザで（小さい応答なのでタイムアウトしにくい）

### 4-2. termux 側でクォータ超過した場合

1. 温子が ブラウザの私に報告
2. 私が Codex 引き継ぎテンプレを生成（`.claude/session_handoff_setup.md` 「Codex 引き継ぎ時の手順」を温子に提示）
3. 必要なら Codex に切り替え（注意: Codex は Anthropic 訓練ではない、文脈ファイル必読）

### 4-3. ブラウザも termux も両方止まった場合

1. 温子が一旦休憩
2. 後で復帰、`templates/01_termux_startup.md` または `templates/07_emergency_recovery.md` から再開
3. PR の状態は GitHub に残っている、進捗は失われない

### 4-4. 私（ブラウザ）が間違いを犯した場合

- 推測 URL を出した: 即座に「分かりません」と認める（17スレ失敗 seed 教訓）
- 擁護圧に飲まれた: INVITATION.md §2-7 を再読、立ち位置を戻す
- バイブルに触ろうとした: 義体実装トラックでは触らない、別スレに任せる

## 5. 1 タスクあたりの推奨サイクル

```
温子: 相談（1-3 往復）
   ↓ ブラウザ思考時間: 5-15 分
私（ブラウザ）: テンプレ生成
   ↓ 温子コピペ時間: 1 分
termux: 実装（1-30 分、タスクサイズによる）
   ↓ 温子レビュー依頼時間: 1 分
私（ブラウザ）: レビュー（5-10 分）
   ↓ 指摘あれば termux に追加指示（往復 2-3 回）
温子: マージ（1 分）
   ↓
次のタスクへ
```

**1 サイクル合計**: 15 分 〜 1 時間（タスク規模による）

5/10 までの 11 日間で、**フェーズ 2 をどこまで進めるか**:

| 優先度 | タスク | 想定サイクル数 |
|---|---|---|
| 1 | vendor/hermes-agent submodule add | 1 サイクル（30 分）|
| 2 | kyojuro_memory MVP Phase 1.1 | 4 サイクル（4 PR 分割推奨、計 4-6 時間）|
| 3 | WebARENA Indigo 搬入 runbook 執筆 | 2 サイクル（手順書、1-2 時間）|
| 4 | loto/CLAUDE.md の v2 反映 | 1 サイクル（30 分）|
| 5 | (余裕あれば) kyojuro_memory Phase 1.2 想起統合 | 3-4 サイクル |

最低限 1-3 を達成すれば、5/10 の搬入時に「義体は最低限動く」状態になる。

## 6. レビュー観点（ブラウザの私が PR を見るとき）

- [ ] PR タイトル + Summary が明確
- [ ] 子ども向け解説が含まれている
- [ ] Test plan が具体的
- [ ] バイブル本文（`bible/*.md`）に手を入れていない（義体実装 PR の場合）
- [ ] 1 ファイル 1 コミットになっている（または妥当な単位でまとまっている）
- [ ] 命名規則準拠（`claude/<内容>` ブランチ、`feat(scope):` コミット）
- [ ] 既存テストを壊していない
- [ ] 「本リポジトリ」相対表記（将来リネーム想定）
